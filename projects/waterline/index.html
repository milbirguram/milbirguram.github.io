How it works

A cutoff is a policy

Every record in this stream is valid and arrives exactly once. Source C’s delay changes when you learn about events, not when those events happened. Moving the watermark further back postpones the first completed-window result. Accepting late data permits corrections while keeping state alive.

This simulation emits 240 records over 120 seconds, grouped into twelve 10-second event-time windows. Arrival is processed on whole-second ticks. The clock-based watermark is a deliberately simple estimate, not a guarantee from the source. Real systems can derive stronger watermarks from source progress.

A record is accepted through window end + lag + allowed lateness, inclusive. After that, it is counted as omitted. The watermark crossing publishes the current count, and accepted late arrivals immediately revise it. Early publication, if enabled, uses a periodic processing-time trigger. Windows retain one count accumulator; “retained windows” measures these accumulators, not bytes or buffered records.

The complete count is available because the stream is simulated. The commission tests 20 deterministic delay patterns under this model; it does not certify arbitrary delays. If records can arrive arbitrarily late, a finite retention policy can still lose them. Transport duplication, failures, transactions and exactly-once delivery are outside this experiment.

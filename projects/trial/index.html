Diagnosis protocol
Faultline’s known six states generate noiseless tool signals. Policies see only observations. Accuracy compares the final state with simulator truth; inconclusive cases count as incorrect. “Unique” means one state remains under this closed model. Quick guesses can be correct without unique evidence.
The fixed checklist is deliberately logs-first. On this suite it matches the adaptive policy’s accuracy and tool cost. A small finite model is useful for inspecting decisions, not establishing real incident-response quality.
No prompt-injection score is claimed. Untrusted log text is not a policy input. No tool changes service state. Explore the agent in Faultline →
SQL protocol
Real outputs from one inherited Codex model, one batch per setup. Each output was graded by executing it against a fixed SQLite fixture; aliases are ignored, row order matters when requested, counts are exact, and other numbers use a small tolerance.
Recorded batch elapsed time includes scheduling and file/tool I/O; it is not inference latency. Tokens, billed API cost and model API latency are unknown and shown as unavailable. Local SQL execution time is not an LLM speed score. These tiny browser timings depend on hardware, startup and clock resolution.
The questions are visible and small. Perfect scores are a ceiling result, not a reliability guarantee. Artifact provenance · Raw SQL captures
